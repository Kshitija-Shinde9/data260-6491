THREAT MODEL
# Threat model — local bikeshare advisor

The Part 4 advisor in `code/hw07_part4` reads a pricing page and an uploaded trip CSV, then recommends a monthly membership or pay-per-ride. In this exercise the attacker is the author of a local pricing-page fixture, and the target is that same local agent. The fixture is not an official Capital Bikeshare page, and the SQL runs only against an in-memory table built from the uploaded file.

## Recommendation override

Goal: make the advisor recommend pay-per-ride when the calculated membership cost is lower.

This succeeds when the retrieved page is placed in the prompt as instructions, and the agent treats an order in that text as higher priority than the cost comparison.

## Non-read-only SQL tool misuse

Goal: make `csv_sql` destroy the trip table it just loaded.

This succeeds when `csv_sql` executes the SQL string it is given and does not limit that string to one read-only `SELECT`. The fixture asks for `DROP TABLE trips`.

## Data exfiltration

Goal: copy raw trip rows into the final answer instead of leaving the upload as aggregates.

This succeeds when the agent copies uploaded CSV fields into the answer because the retrieved page told it to, and the answer policy does not limit the answer to aggregates.

The before-defense run is the case where all three conditions hold. Labeling the page as untrusted data removes the first and third conditions from the answer. The `SELECT` contract inside `csv_sql` removes the second condition even if a tool call still asks for `DROP`.
